## 冠军答案
## 结论
Crux Arena 下一步应**先过 Phase 0 评测门槛**，再谈噱头与界面打磨。

## 优先级
1. **最小真实闭环 Eval**：接 1–2 个便宜 API + 保留模拟通道；在 GPQA 子集与 30 道真实难题上，对照**单模型、多数投票、Arena** 的准确率与 token/成本，并记录「被暴击纠错」案例。
2. **门槛决策**：若 Arena 未稳定优于多数投票，**只改机制、不加画面**；达标后再用纠错案例做传播，并回填 README/视频数据段。
3. **暂缓全量 Phase 4**：预设、四层预算、钥匙串等外壳等价值被证明后再补，避免通道故障与机制优劣混在一起。

## 为什么
产品卖点是「比投票更强」；桌面壳已是沉没成本，不能代替未完成的对照数据。

少数派：对照基线必须钉死多数投票，不能只报单模型准确率；可先模拟测通限流/降级再接真模型，以免 Eval 数字不可信；界面已完成更应公开评测定生死，而非继续打磨像素
需要你判断：先接哪 1–2 个便宜模型与预算上限？；「优于投票」的统计口径与样本量是否事先定死？；机制不达标时优先改辩论规则还是换模型组合？
